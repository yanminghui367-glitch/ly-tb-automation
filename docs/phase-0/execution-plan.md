# ly-tb-automation 标准执行方案

> 适用范围：两名用户异地协作的私有淘宝商品生产系统。  
> 执行原则：一步一验收；当前步骤未确认前，不无边界扩展下一阶段。

## 1. 已确认的最终呈现方式

系统最终呈现为一个**私有中文浏览器管理后台**：

```text
用户 A ── 浏览器 ──┐
                    ├── 私有管理后台（固定 Windows 主机）
用户 B ── 浏览器 ──┘           ├── FastAPI 单体应用
                               ├── SQLite
                               ├── 图片与商品包目录
                               ├── 商品生成 Worker
                               ├── 日志与自动备份
                               └── 淘宝 RPA 执行环境
```

MVP 不建设公开 SaaS、桌面双端、手机 App、多租户或微服务。两名用户使用独立账号，通过私有网络访问唯一一套服务和数据。

## 2. 使用体验目标

非技术用户只需要浏览器即可完成：

1. 导入并校验国家、城市和素材数据。
2. 创建国家级或城市级商品生产批次。
3. 查看标题、主图、副图、详情和质检结果。
4. 编辑、退回或批准商品。
5. 将已批准商品加入发布队列。
6. 查看 RPA 进度、错误截图和淘宝商品 ID。
7. 查看备份状态和必要的运行告警。

系统不得要求日常运营人员运行命令、编辑 JSON、直接操作 SQLite 或手工同步两台电脑的数据目录。

## 3. 产品页面范围

### 3.1 工作台

展示待处理事项，而不是复杂报表：待生成、待审核、待发布、发布失败、素材缺失、执行机状态和最近备份时间。

### 3.2 目的地与素材

支持 Excel 导入、逐行校验、国家/城市维护、核心城市和优先级、服务覆盖、城市图片及授权状态。

### 3.3 商品生产

支持批次创建、进度查看、失败原因、标题 A/B、图片与详情预览、局部重新生成和商品包下载。

### 3.4 商品审核

支持选择或编辑标题、切换模板、重新生成图片、审核通过、退回原因，以及审核人和修改历史。

### 3.5 发布中心

支持发布前检查、人工启动小批次、逐件状态、失败截图、有限重试和人工接管。早期默认保存淘宝草稿，不默认正式发布。

### 3.6 系统设置

只提供必要设置：标题规则、模板、淘宝字段映射、批次大小、AI 开关/预算、用户、RPA 状态和备份状态。

## 4. 部署基线

### 4.1 单节点优先

第一版在一台固定在线的 Windows 主机上运行后台、数据库、文件、Worker 和 RPA，避免过早引入跨机器文件同步与任务通信。

建议数据目录与代码目录分离：

```text
<data-root>/
├── database/ly_tb.db
├── assets/
│   ├── templates/
│   ├── city_images/
│   ├── fonts/
│   └── logos/
├── products/
├── logs/
├── rpa_screenshots/
└── backups/
```

### 4.2 访问与账号

- 后台只通过私有网络访问，不开放公众注册。
- 两人各自使用独立账号，不共享登录身份。
- 初期角色只设管理员和运营人员。
- 淘宝登录凭据和 API Key 不保存到普通业务表。
- 审核、重生成、发布、重试和配置修改写入审计记录。

### 4.3 数据与备份

- SQLite 文件只放在中心主机本地磁盘，禁止通过同步盘让多台电脑直接共同打开。
- 所有业务读写经应用服务完成。
- 数据库每日备份；素材、模板、已发布商品包和日志按策略备份。
- 备份必须定期执行恢复演练；“产生了备份文件”不等于“可以恢复”。

## 5. 分阶段执行与验收门

### Step 0：项目治理与需求基线（已完成）

**交付物**

- Role / Persona 和工程执行规范。
- 目标部署架构。
- Phase 0 决策与待确认清单。
- GitHub Skills 引入与安全审查规则。

**通过条件**

- 两人使用方式和中心主机方案确认。
- 首批国家/城市范围确认。
- 淘宝真实发布字段资料开始收集。

### Step 1：工程骨架

**范围**

- Python 项目结构、依赖锁定和配置分层。
- FastAPI 健康检查与服务端页面骨架。
- SQLite 数据库、迁移机制和本地开发启动方式。
- 结构化日志、基础测试、格式与静态检查。
- Windows 一键启动脚本和配置示例。

**通过条件**

- 新环境可按文档启动。
- 健康检查、数据库初始化和自动化测试通过。
- 无真实密钥进入 Git。

### Step 2：目的地数据中心

实现国家、城市、服务类型、Excel 模板、导入校验、重复检测和导入报告。

**通过条件**：合法数据可重复导入且结果幂等；缺字段、非法国家、重复城市均定位到具体行。

### Step 3：商品任务与标题规则

实现国家级/城市级商品、批次任务、状态机、两个标题候选、规则版本和人工选择。

**当前状态**：工程能力已完成；标题模板、服务覆盖和淘宝平台规则仍以待确认草稿门禁处理。

**通过条件**：单任务失败不影响其他任务；同一输入重跑结果确定；批准内容不会被静默覆盖。

### Step 4：素材与渲染

先一次性生成 10 张美国目的地主图候选，在尽量固定核心文案、信息层级和素材条件的前提下比较版式，人工批准 1 个全店统一主图模板版本。随后实现模板注册和素材校验；Pillow 使用该版本为每条链接渲染 1 张目的地主图并处理长名称。全店另一次性制作 4 张可选择复用的副图、2 张详情首图和 7 张详情内容图，作为共享版本化资产加载，不随商品任务重复制作。

**通过条件**：10 张美国候选图及选中结果可追踪且仅有 1 个模板版本获批；标准、缺失、损坏和长名称素材用例均有自动检查；相同商品重跑统一主图模板版本不漂移；18 个验收商品按配置选择共享副图并引用同一组 2 张详情首图和 7 张详情内容图，单个商品重跑不会改写共享资产。

### Step 5：质检、审核与商品包

实现 ERROR/WARNING/INFO、审核流、修改历史、预览、版本化商品包和 Excel/CSV 导出。

**通过条件**：18 个试验商品可批量生成、逐件审核和独立导出，且无需调用 AI。

### Step 6：人工发布验证

由人工使用生成商品包发布少量测试商品，记录淘宝类目、字段、图片、详情和审核结果，完善字段映射。

**通过条件**：内部 `manifest` 能完整表达真实发布字段；所有例外有规则或人工入口。

### Step 7：RPA PoC

对同一组 10 个审核商品评估候选 RPA，先只打开页面，再自动填写，最后保存草稿。

**通过条件**：可记录步骤、截图和失败原因；登录失效/验证码能暂停并人工接管；不执行无限重试。

### Step 8：小批量正式发布

每批 5～10 件，人工启动，逐件发布并回写淘宝商品 ID。

**通过条件**：重复发布可阻断，结果未知可转人工，失败任务可安全重试，发布记录可审计。

### Step 9：稳定运行与按需扩展

根据真实指标决定是否拆分 PostgreSQL、对象存储、任务队列或多个 RPA 节点。没有测量到的瓶颈，不提前升级架构。

## 6. 每步统一完成定义

每个步骤只有同时满足以下条件才算完成：

1. 需求和验收标准已记录。
2. 设计考虑正常、失败、重复和恢复路径。
3. 实现范围没有越过当前阶段边界。
4. 自动化测试和相关静态检查通过。
5. Windows 目标环境的操作方式已考虑。
6. 用户文档、配置示例和变更记录已同步。
7. 不包含密钥、个人数据或淘宝登录信息。
8. 提交和 PR 清晰说明变更、测试、限制与下一步。

## 7. GitHub Skills 评估流程

Skill 不是必装依赖。每次只为一个明确任务选择候选项：

1. 从 OpenAI 官方 curated 列表开始检索。
2. 阅读候选项的 `SKILL.md` 和全部可执行脚本。
3. 比较其与内置工具及简单项目脚本的收益。
4. 检查来源、许可证、维护状态、依赖、网络和文件写入行为。
5. 记录选择或拒绝理由；第三方 Skill 必须固定提交版本。
6. 在隔离输入上试用，通过后才用于项目工作流。
7. Skill 输出仍需经过项目测试与人工审查。

当前环境访问 GitHub API 时受到网络代理限制。在恢复访问前，不绕过审查流程，不下载来源不明的替代包；项目开发可使用内置能力继续推进。

## 8. 当前决策状态

以下 Step 0 输入已在 2026-08-22 确认：

1. 工程适配固定 Windows 中心节点，但暂不锁定家中电脑、专用小主机或云服务器。
2. 两名用户都可审核商品，仅管理员可启动正式发布。
3. MVP 使用日本、法国、越南各 5 个城市作为 18 商品验收数据集。
4. 正式主图批量生成前，先用 10 张美国目的地主图候选选定统一模板。
5. 每条链接只生成 1 张目的地主图；4 张副图选择性复用，2 张详情首图和 7 张详情内容图全店共享。

详细内容见 [Phase 0 决策记录](decision-log.md)。淘宝类目与发布字段可在工程骨架之后继续补充，但进入真实发布适配前必须确认。
