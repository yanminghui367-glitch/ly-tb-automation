## 本地 Web 工作台 V1（2026-09-21）

日常使用双击根目录 **`启动上架工作台.vbs`**（原 `打开旅行上架工作台.cmd` 也可用），浏览器会打开 <http://127.0.0.1:4318/>。本机 Node.js、Python、Chrome 和项目独立依赖已就绪；日常启动不需要 Codex 或命令行。重复打开复用同一个服务。系统设置中的“暂停并退出程序”会保留断点，下次启动复用项目专用 Chrome 登录。

六个入口：首页仪表盘、任务中心、实时执行监控、异常中心、上架记录、系统设置。先检查登录 → 导入商品 Excel 与图片（高级项保留热度表）→ 识别并核对字段及全部素材 → 生成任务 → 开始执行。生成任务不会自动执行。默认只检查首条并在提交前暂停；正式批次须明确选择“正式上架”。验证码仅人工处理，保留原页面后确认继续；成功商品自动排除，结果不明仅核验。

**当前保持执行关闭，累计 30 条成功记录和已完成的 20 条批次不变。** 本轮不新增真实商品。需要执行时在设置开启，再到任务中心手动开始；每批最多 20 条，不自动续批。V1 复用并校验 `kernel-lock.json` 中冻结的 10 个内核文件，旧工具保留在 `legacy.html`。验收证据：`output/workbench-v1-20260921/REPORT.md`。以下为历史版本记录，不代表当前功能边界。

## 2026-09-21：热度批量任务队列

首页“批量上架”只读关联热度表 `境外城市热度` 与已确认的 700 商品池，预览后冻结最多 20 条任务。SQLite 保存唯一任务编号、七种任务状态、步骤断点及平台结果；成功任务不再提交，提交结果不明只核验。验证码暂停整批，人工处理后点“继续”；普通失败只接受手动有限重试，每条最多 3 次。

支持开始、暂停、继续、重试失败、统计与报告；默认仅填写。本轮真实 20/20 条已发布并逐条查验后台，队列已停止，未启动第 21 条；过程中有修复、重试及异常重启恢复，不是无人干预压测。报告见 `output/batch20-20260921/REPORT.md`，当前状态见 `docs/PROJECT_STATUS.md`。旧版本说明保留其历史适用范围。

## V2 自动上架引擎（2026-09-17）

新增独立命令行引擎：只读Excel适配、标准PublishTask、SQLite状态机、逐步回读校验、验证码checkpoint、提交结果核验及断点恢复。入口见 [V2运行说明](engine/v2/README.md)、[重构审计](docs/V2_REFACTOR_AUDIT.md)和[V2验收报告](docs/V2_P0_QA_2026-09-17.md)。当前已通过本地合成页面验证，真实淘宝单条发布及平台1/5/20/50压测尚未验收；旧工作台仍沿用下述DRY_RUN边界。

本项目是本地运行的旅游商品上架工作台。当前可用范围是：导入已生成的商品包、保存本地队列、管理独立 Chrome 会话、记录发布审核证据、配置经人工验证的字段映射，并将合格商品按映射填写到淘宝草稿提交前；任务会持续汇总风险、人工处理、草稿核验和可继续执行的下一步。

当前**不是**可自动发布系统：不点击最终提交、不写回商品 ID/链接，也不会绕过登录、验证码、滑块或风控。字段填写、图片上传与原生下拉选择仅在五项审核证据和页面映射均通过后进入 `DRY_RUN`；每步留截图，最终提交前自动暂停等待人工核验。

## 启动

双击 `打开旅行上架工作台.cmd`，或在 `workbench/` 执行：

```powershell
npm install
npm run check
npm start
```

工作台仅绑定 `http://127.0.0.1:4318`。每个店铺使用独立 Chrome 配置目录；密码、Cookie 和验证码只由操作者在淘宝页面处理。
