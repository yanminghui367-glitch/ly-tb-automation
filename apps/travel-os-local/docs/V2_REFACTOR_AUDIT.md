## 3. V2模块与边界

`只读Excel/商品包/素材 → adapter → PublishTask → SQLite → runner → PageObject/selector registry → 核验/结果/checkpoint`

1. 适配层：标准任务与来源哈希；热度只在此层排序，执行器不读取Excel、不计算热度。
2. 独立SQLite：不可变任务、状态、步骤checkpoint、事件、提交意图和结果；事务与进程互斥，断电重启不丢失已确认状态。
3. 页面层：集中定位器、身份和风险校验，逐步验证字段值/上传回显；禁止坐标点击、固定等待、未经核验的淘宝selector。
4. 执行层：默认DRY_RUN；LIVE有绑定对象版本的准入。提交前先持久化意图；提交后超时/崩溃进入RESULT_UNKNOWN，禁止自动重新提交。
5. 恢复：验证当前页面与checkpoint，不盲跳旧步骤。验证码立即停止后续动作、落盘截图与人工提示；人工处理后显式恢复当前任务。一次只跑一个商品。

## 4. 验收计划

先单条本地真实浏览器全流程，再1/5/20/50任务阶梯压测，分别记录首次成功率、恢复后成功率、失败原因、耗时、证据路径。故障覆盖验证码、页面变化、断开/重启、结果不明和去重。合成页面成绩明确标记LOCAL_FIXTURE，不冒充淘宝成绩。

真实P4/P5需要当前商品资料、店铺身份、字段映射和版本绑定的QA记录。缺项不阻塞开发，但阻塞真实动作；不得为了跑通复制旧20元/999999等候选值。

官方依据：[Playwright动作可执行性](https://playwright.dev/docs/actionability)、[Locator条件等待](https://playwright.dev/docs/api/class-locator)、[Node SQLite](https://nodejs.org/api/sqlite.html)。本机已核验Node v24.18.0、SQLite内建模块和Playwright可加载；SQLite在该运行时的实验性警告保留记录。
