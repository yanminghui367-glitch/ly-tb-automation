# 星途当前使用与恢复流程｜2026-11-04

本页对应正式源码 `20261103-stability-recheck-r2`、92项内核。安装源码、资料准备、任务执行和淘宝实际发布是不同步骤；下载、导入或检查通过不会自动上架。

## 新电脑首次使用

1. 下载公开仓库 `ly-tb-automation` 的 `main`，运行根目录“安装星途工作台.cmd”；也可进入 `apps/travel-os-local/` 运行“安装工作台.cmd”。需要Windows、Node.js 24+、Python 3.10+和Google Chrome；安装器使用依赖锁文件并核验源码与内核。
2. 在应用目录运行“启动上架工作台.vbs”，打开本机工作台。独立运行的新电脑需要导入资料；若只是另一台电脑访问现有局域网主机，只访问该主机当前显示的地址，不另开一套执行系统。
3. 在“资料设置”选择主机存储位置，导入本店资料包，再通过“店铺连接”入口打开本店专用执行Chrome并由操作者人工登录。验证码、滑块和店铺身份确认都由人工处理。
4. 检查准备情况、核对商品与执行许可，再选择明确范围。安装和检查本身不会发布。已有历史需使用独立本地业务迁移包恢复，不能把新电脑的空历史库当作老店已发布记录；禁止复制浏览器登录配置或凭证。

## 资料标准与更新

一个店铺一套资料。标准 `商品资料.xlsx` 的“商品清单”是10列：序号、国家或地区、城市、链接类型、标题一、标题二、使用标题、导购标题、售价、库存。序号是固定识别号，不按行顺序猜图；国家链接城市留空，城市链接必须填城市。店铺设置还需填写经核实的店铺识别码及真实业务配置。

图片目录、命名和版本遵循 [商品识别模板v2](PRODUCT_IDENTIFICATION_TEMPLATE_V2.md) 与 [导入标准](SETUP_IMPORT_STANDARD_SYNC_20261014.md)。国家主图含店铺码/序号/国家，城市主图含店铺码/序号/国家/城市；每张图独立版本，同一素材不得混放多个版本或扩展名。现有旧资料沿旧格式使用，不为换电脑批量改名。

资料有误时回Excel或图片文件夹修改，再重新导入核对。既有冻结任务保留原资料快照和随机结果；新导入不代表旧任务已自动换图。副图整套随机、首页随机及允许的属性候选须先确认；任务内固定，不在重试时换一套随机结果。国家标题使用“国家＋服务关键词”，城市标题使用“城市＋国家＋服务关键词”，不得漏掉城市或国家。

## 商品总表与范围

先选对店铺及资料包，再进入产品库总表。按等待执行、执行中、已发布并核验、异常、待人工、结果待核验、资料待补或已跳过等状态筛选，并可结合目的地、标题、商品ID和国家定位。表头全选针对当前筛选结果，所有状态可选；“可勾选”不等于“允许重试或再次提交”，实际动作仍由后端核对原状态、提交证据、额度和授权范围。

日常流程为“换资料 → 检查准备情况 → 总表选择 → 预检 → 确认执行”。可以管理多个店铺，当前按单店单执行器串行工作，不把多店同时运行视为已验收功能。

## 图片准备与复用

已有合法准备回执的图片按店铺、源文件SHA、版本及平台卡片复用；新传图片分批准备，保留逐图回执及原任务恢复记录。上传结果未定时先核查原图片任务，不再次选择同一文件。正文顺序、首页选择和每条副图套组均沿用原冻结任务；不是每个商品重新上传共享图片。

当前集中准备入口对没有准备回执的图片会进入待传清单；“原文件名已经在淘宝库中”不等于已有集中回执。因此先检索已有主图，确认缺少才补传，不能把无回执或一次空结果直接视为缺图，也不要给原名图片伪造SHA上传回执。原名图片无新版绑定时，现行发布器可按原basename复用；新版绑定图片仍必须满足原回执校验。

本次环球领航原372—700共329张主图经完整素材索引与原图比对确认已存在；每条4副图＋9详情共4277处引用复用18份共享资源，已核对原回执及平台记录，补传0。329主图均无materialVersion，现行原名复用适用，故这批不再点击集中准备去重传。淘宝CDN有损压缩后文件SHA可能不同，不以此判定缺图。本次核对仅代表当时素材可用，后续素材库或源文件改变需要重核。

## 执行、停止与恢复

执行前核对选店、原商品清单、版本和实际类目/属性/价格/库存/物流等事实。明确确认是否发布及所选范围；单窗口最多100条，自动衔接是否开启以本次确认范围为准。需要有界样本时明确数量并关闭自动衔接，不能沿用旧100条窗口假定它会自动停在样本数。

| 现象 | 网站中的处理原则 |
|---|---|
| 单商品资料缺少或明确未提交的可恢复故障 | 按详情定位原行/原图；修正后用原预检或合法重试入口，不重建任务绕过额度 |
| 提交前的短暂页面/素材等待异常 | 现行执行器做有界等待及安全步恢复；耗尽后记录单条失败，系统连续故障仍可熔断 |
| 验证码、登录失效、店铺身份问题 | 打开对应专用Chrome人工处理，再用原检查/继续入口；不绕过、不抽样忽略这些检查 |
| 已点击提交但结果不明 | 仅核验原商品；禁止普通跳过、自动重试或重新提交 |
| 核验已尝试但仍无唯一匹配或时间不符 | 满足页面能力及原核验证据条件后，填写确认人与原因，使用独立“挂起并继续”入口；仍保留结果未知、提交标记、分母及待核计数，报告单列人工确认 |
| 跳过按钮灰色 | 查看原详情给出的能力/阻塞原因；已提交保护不能用普通跳过解除，不能直接改数据库清除状态 |
| 额度耗尽 | 先处理根因，只有明确授权且现行后端允许时才由人工追加；保留审计、原attempts及上限，不建新任务绕过 |
| 窗口已结束或手动停止 | 核对结项和未处理范围；开始下一窗口需明确选择，不把“已结束”当作“全部上架成功” |

成功必须有平台商品ID及结果核验，不能只凭绿色内核、登录成功或提交点击计为成功。当前平台类目/商品表达的接受结果仍依平台与真实业务条件，源码同步不能证明类目合规。暂停/停止保留原记录；已成功或未知提交不得重发。
