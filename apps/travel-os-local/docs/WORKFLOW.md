# 目标工作流与状态流转｜P1

## 主流程

登录店铺 → 检查 Chrome/淘宝登录 → 上传商品包 → 解析 → 文件与字段校验 → 识别国家/城市 → 生成或选择两个标题 → 匹配图片与详情 → 同店国家/城市单链接重复检测 → 商品预览 → 人工审核 → 创建发布任务 → 浏览器自动填写 → 提交发布 → 获取商品 ID/链接 → 保存结果 → 异常修复与重试。

## 商品状态

`IMPORTED` → `FILE_BLOCKED` / `FIELDS_BLOCKED` → `READY_FOR_REVIEW` → `APPROVED` → `QUEUED` → `RUNNING` → `PUBLISHED` / `FAILED` / `PAUSED`。

当前的 JSON `READY` 仅映射到 `IMPORTED` 后的文件检查结果，不能跳过字段、审核和发布门槛。`NEEDS_REVIEW` 商品包也可进入工作台以获得审核反馈，但始终停留在 `FIELDS_BLOCKED/READY_FOR_REVIEW`，直到操作人填入真实资料、完成核验并重新标为 `READY`。

## 任务状态

`DRAFT` → `VALIDATING` → `WAITING_FOR_REVIEW` → `QUEUED` → `RUNNING` → `PAUSED` / `COMPLETED` / `FAILED` / `CANCELLED`。

若登录失效、验证码、风控、页面结构变化、类目不匹配、必填字段缺失、连续失败或图片错位，任务立即进入 `PAUSED`，保留当前步骤、截图和可恢复信息。

若因滑块、验证码、登录失效或其他风控恢复，操作人必须先在专用 Chrome 手动完成处理，再在工作台填写本次人工处理结果（可附截图、录屏或可复核链接）后恢复。恢复会重新进入队列并从已验证草稿页开始；已经由执行器成功填写、选择或上传的字段会保留完成记录，不会因风险检查在动作完成后触发而被重复执行。

若执行前再次发现当前导入记录中存在同店、同国家级或同城市级商品包，任务进入 `PAUSED/DUPLICATE_LISTING_DETECTED`，不打开卖家页面。操作人保留一条并重新导入后，取消旧任务再创建新的 DRY_RUN；工作台不自动删除、合并或判定淘宝线上已有商品。

对于商品包、商品包快照变化或缺失、审核资料、店铺、字段映射、字段值、页面定位或本地重复检测导致的非风控暂停，操作人可填写原因把当前条目标记为 `ISOLATED`。这只会让剩余条目回到 `QUEUED/NEXT_ITEM_READY`，并要求再次人工开始；隔离操作不会新开卖家页或自动续跑。若整批均已隔离，任务进入 `COMPLETED_WITH_ISOLATIONS`，并明确表示隔离操作未提交或发布。`PAUSED_RISK_CONTROL`、`RISK_PAUSED`、`MANUAL_FIELD_REQUIRED` 和 `FINAL_REVIEW_REQUIRED` 不允许隔离，必须在原人工流程中处理。

任务创建时会冻结字段映射摘要和商品包执行快照。开始 DRY_RUN 前若映射版本、页面证据、草稿页地址，或任一字段的来源/定位器/交互方式/逐项核验状态/必填规则、字段清单或执行顺序发生变化，任务进入 `PAUSED/MAPPING_CHANGED_SINCE_REVIEW`；当前映射若未通过重新校验则先进入 `PAUSED/MAPPING_INVALID`。若目的地、标题、素材、类目/价格/履约资料或审核证据在创建任务后发生变化，任务进入 `PAUSED/PACKAGE_CHANGED_SINCE_REVIEW`。旧任务缺少映射或商品包快照、或仍使用仅含六项字段的旧版映射快照也会暂停。所有此类情况均不打开卖家页面，必须重新审核、核验后取消旧任务并新建。

批量 DRY_RUN 在每一条商品填充至提交前时都必须暂停并由人工核验。操作人必须记录核验结论（可附提交前截图、录屏位置或可复核链接），再完成当前条的 DRY_RUN 记录；若批次还有未处理商品，任务回到 `QUEUED` 并等待人工再次开始下一条；只有批内每条均已核验才会进入 `COMPLETED`。任何一次核验都不会提交或发布商品。

## 幂等与恢复

每条任务使用内部商品 ID + 店铺 ID + 商品包版本生成幂等键。重新导入不能覆盖已发布结果；正在进行中的任务所引用商品包，即使本次导入未包含，也会保留到任务结束，避免后续恢复变成“商品包不存在”。重试只处理未发布且通过复核的条目。成功依据必须是淘宝返回的商品 ID 和链接，而不是页面按钮点击或本地状态。

## 监督审计导出

每个 DRY_RUN 任务可从“查看记录”导出本机任务审计包，包含任务状态、每条商品创建任务时的准入结论、字段完成情况、人工恢复/隔离记录及工作台生成的截图引用。导出会剔除账号、Cookie、素材绝对路径、字段定位器和外部证据链接，且不把草稿完成误写为淘宝发布成功。

## N02执行前会话核验（2026-09-13现行补充）

先在专用Chrome手动打开映射中已审核的目标草稿页，核对店铺名称及其真实CSS位置，再在工作台完成会话确认。归属、人工身份确认和商品闸门都通过后，执行器才在该页操作；不会自动另开页或导航后继承旧确认。确认10分钟到期，切页、断线或配置变化需重做。

SESSION_REVALIDATION_FAILED允许重新确认后将原任务重新排队；风控暂停仍沿用人工处理记录与恢复流程。忙时暂停/取消返回409并使会话失效，当前已发出的单个动作不能撤销，须按提示重试保存。实际边界与证据见 [N02记录](SESSION_GUARD_2026-09-13.md)。
