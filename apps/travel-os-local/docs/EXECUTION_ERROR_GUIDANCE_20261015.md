# 执行异常原因与处理办法｜2026-10-15

适用于网站自动化任务的本轮执行监控。系统异常暂停时，在商品名称及当前步骤下直接显示“异常原因”和“处理办法”，不再要求操作者先展开日志才能判断。

`workbench/ui-copy.js` 的 `diagnose` 根据现有错误标识、原任务状态与提交标记生成展示文案；`travel-os.js` 显示本轮原因，避免被商品的历史错误覆盖。已知错误包括资料版本变化、文件缺失、内核版本不一致、登录或验证码、运费模板、无规格核对、图片规格与内容、恢复条件、页面等待及连接失败。没有可靠对应原因时明确显示“异常原因待确认”，不猜测为登录或资料问题。

资料哈希变化明确解释为原任务与当前文件版本不一致，提示核对资料设置和原任务版本绑定；不声称重新开始一轮会自动替换旧快照。提交结果不明、已提交或提交不确定时优先提示核验原商品，禁止用资料修复提示引导重复提交。

本次只修改展示文案和监控渲染，不修改商品资料、任务快照、记录、次数、执行权限或发布流程。此功能本身不修复资料绑定，也不自动恢复任务。

验证使用 `scripts/ui-copy.test.mjs` 及既有状态/任务投影针对回归；页面由既有QA使用随机本地端口和合成数据检查，包含桌面、手机、旧错误与当前原因优先级、未知原因和提交保护。旧监控脚本的历史商品选择器与现界面不匹配，本次未将其失败当作新增诊断通过依据；独立证据见 `output/error-guidance-20261015/` 及既有QA的本轮输出。最终版本与维护加载以 `PROJECT_STATUS.md` 顶部为准。
