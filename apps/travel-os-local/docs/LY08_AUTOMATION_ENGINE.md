# LY｜08 淘宝自动化上架引擎

日期：2026-09-12。本轮仅完成“完整字段映射冻结与执行前复核”，属于 P3/P4 引擎代码加固；不代表真实淘宝 P4 验收或 P5/P6 放行。LIVE 保持关闭。

## 已有能力与本轮问题

现有 `workbench/server.mjs` 已实现 DRY_RUN 字段填写、原生下拉选择、图片上传、字段截图、风险暂停、人工恢复及最终提交前停止。本轮沿用该引擎，没有重建或添加提交动作。

旧映射快照只保留六项基础字段，并按 ID 排序；执行器实际遍历整个 `mapping.fields` 数组。库存等额外字段的来源、定位器、交互方式、增删，以及字段顺序和 `required` 改动可能不改变旧指纹。此外，旧校验只要求六项基础字段有 `reviewed: true`。

## 本轮修复

- `mappingSnapshot` 使用 `snapshotVersion: 2`，按实际执行顺序冻结全部字段及必填规则；不排序、不筛除额外属性。
- 差异记录明确指出字段清单/顺序、对应字段或快照格式变化。旧任务不会自动补写新快照；必须取消后重新审核建任务。
- 所有映射字段，包括可选字段和人工字段，都必须逐项核验。`required` 只接受布尔值或省略，省略等同于 `true`。
- `createTask` 与 `executeNextDryRun` 重新校验当前映射，不依赖历史 `mappingValidation.valid` 缓存。无效映射阻塞创建或暂停执行；有效但改变的映射按原有 `MAPPING_CHANGED_SINCE_REVIEW` 路径暂停。
- 六项基础字段仍通过现有核验清单录入；额外字段目前须由操作人在当前页面核验后，在映射 JSON 中填写 `reviewed: true`。本轮未改 UI。
