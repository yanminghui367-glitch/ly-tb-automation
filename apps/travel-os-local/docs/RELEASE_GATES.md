## 模式及共同条件

- REVIEW：整理、导入、预览和人工审核。
- DRY_RUN：通过下述 P4 准入后，填写至最终提交前停止；默认执行模式。
- LIVE：最终提交；默认关闭，现有执行器不具备提交能力，不能靠配置切换获得。

P4/P5/P6 都必须核验：目标店铺、会话归属和登录身份；目标店铺当前页面的真实类目和完整属性；商品真实供给、价格、库存承接依据、退改、售后和资质；标题、国家/城市、主图与4副图、固定详情顺序及内容一致；授权覆盖实际对象及版本；线上同目的地已有链接核对。文件 READY 标签、CDP connected 和本地去重均不能代替这些证据。

## P4：首次真实填写至提交前

1. 共同条件有可追溯证据，商品包强校验和五项审核证据通过，当前页面字段逐项核验并冻结版本。
2. 静态资源访问边界、会话归属和身份核验缺口修复并由 QA 复验；关键任务闸门离线测试通过。
3. 明确单条商品、店铺及本次测试范围，操作者已在专用浏览器人工登录。风险、验证或字段失效时立即停止。
4. 每字段留截图与事件，最后停在提交前。暂停、登录失效、验证、隔离和恢复能力按适用场景验证；不通过则该场景仍阻塞 P5。

P4 不要求先有成功发布记录；P4 完成的证据是同一对象和版本的真实页面记录及人工草稿核验，不是合成测试结果。

## P5：首次单条真实发布验收

1. P4 通过且留存同一商品/店铺/映射版本的真实截图、日志及草稿核验。
2. 共同条件重新复核；暂停、风险处理、登录失效、失败隔离、恢复及结果记录的适用测试无未解决阻塞。
3. 从用户已有授权和章程核对本条发布对象与范围，明确单店、单条、选定标题、商品包和映射版本。授权已经覆盖时不重复询问；对象或范围无法确定时只补充该信息。
4. QA 给出带证据的单条放行记录。自动提交能力若另行开发，须另验收；当前版本只能在闸门通过且授权明确后由人工最终提交，不能声称工作台可自动发布。
5. 提交后必须取得平台真实商品 ID、链接和状态核验，关联对象、版本、操作者及时间。超时或结果不明进入“结果待核验”，先查平台，禁止盲目重试导致重复。

**首次 P5 无须预先成功发布另一条。成功发布是本阶段验收结果。**

## P6：批量准入

1. 已有一条真实 P5 成功记录，包括商品 ID/链接和可追溯证据。
2. 批次每条均满足共同条件；明确清单、店铺、数量和冻结版本，用户授权覆盖该批次。单条授权不自行扩展为整批。
3. QA 复验批次去重、失败隔离、风险暂停、人工处理、恢复和结果不明处理；批量执行及结果记录能力已实测。
4. 总负责人根据 QA 结论和明确范围组织执行；任一资料或映射改变重新审核。达到 700 条是规模目标，不能用创建 700 份文件替代实际结果。

## 每次执行前与执行中复核

创建任务后、打开卖家页前再次检查 READY、商品包强校验、五项证据、字段映射、任务快照和店铺归属；任何变化先暂停，不导航淘宝页面。

打开页面后、每个填写/选择/上传动作后、最终人工核验前检查验证码、图形/短信验证、滑块/人机验证、安全/行为验证、异常访问、登录失效和 CAPTCHA。命中只留证并暂停，由人工合法处理；不得绕过。恢复须确认页面及身份仍匹配，不把历史已填字段等同于当前页面已保存。

审核记录至少包含：审核人角色及实际身份（未知则待确认）、时间、店铺、商品/批次、版本或哈希、来源、测试证据、授权引用、决定和原因。编写制度或通过离线检查不形成平台放行。

当前是否放行以 PROJECT_STATUS.md 和对应 QA 证据为准；本次修订没有消除历史业务和会话阻塞。
