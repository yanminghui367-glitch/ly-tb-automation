## 查证顺序

1. 从知识库查原件和既有结果，先判断版本及适用范围，避免重复调研。
2. 根据问题选择上表渠道；页面事实只对对应店铺、类目、采集时间有效。
3. 使用一手资料回答事实；二手文章、同行商品、搜索摘要仅作为寻找原件的线索。
4. 出现矛盾时保留双方来源及适用日期，标记“冲突待核验”；任务不能选择更方便的口径继续发布。
5. 原件无法取得时记录缺项、责任岗位、受影响步骤和解除条件，不生成猜测字段。

## 采集记录模板

```yaml
source_id: S-xx-YYYYMMDD-001
question: 待核验问题
channel: 对应渠道编号
url_or_local_reference: 待采集
publisher_or_provider: 待核验
collected_at: 待采集
effective_at: 待核验
scope: 店铺/类目/目的地/服务/版本
claim: 原件支持的具体事实
evidence_reference: 脱敏截图或原件路径及哈希
limitations: 不支持哪些判断
reviewer: 待指定
status: 待核验
refresh_trigger: 页面/业务/版本变更或有效期到期
```

更新时间是采集时间，不能代替规则生效时间。链接不可访问、页面改版、供给失效或版本改变时，关联结论先改为“需复核”。本步骤只建管理机制，不启用抓取、定时任务或自动登录。
