# 证据与验证规则

建立日期：2026-09-13。范围：第 6 步。治理细则；不改变 [发布门槛](../RELEASE_GATES.md)，不代表已实现软件强制校验。

## 证据分层

| 层级 | 可证明什么 | 最低证据 | 不能推出什么 |
| --- | --- | --- | --- |
| E0 意图/候选 | 用户希望做什么、待研究什么 | 原指令或可追溯本地记录 | 不能推出平台允许、真实供给或实现成功 |
| E1 文件/代码 | 文件存在、结构、语法或代码中有实现 | 文件路径、检查时间、版本/哈希、校验记录 | 不能推出图片内容正确、业务真实或代码已运行 |
| E2 本地功能 | 在明确测试环境下某行为通过/失败 | 测试版本、命令、退出码、断言结果、完整日志 | 合成素材、测试替身、离线测试不能冒充平台验收 |
| E3 业务与页面 | 指定店铺和商品的真实资料、当前字段及提交前执行 | 人工核实记录、供给/规则引用、映射/商品哈希、当前页面截图与日志 | 提交前页面、保存草稿或按钮可用不等于发布成功 |
| E4 平台结果 | 明确授权范围内某条商品实际发布的结果 | 授权记录、店铺、商品ID/链接、平台状态、时间、商品/映射版本、结果核验 | 单条成功不证明批量可放行或其余商品已发布 |

每次结论必须写“对象＋版本＋时间＋验证范围＋结果＋限制”。允许状态：待核验、已验证（注明层级）、失败、冲突、已失效。不得将“有路径”“非空文字”“字段reviewed=true”作为内容审核完成。

## 对接当前五项审核字段

以下字段名来自 [服务端](../../workbench/server.mjs) 的 `releaseEvidenceRules`。当前非空引用检查不核实资料真伪；此表规定人工/QA最低核验内容。

| 字段 | 必须核实的事实 | 验收资料与失效条件 |
| --- | --- | --- |
| category_and_attributes | 目标店铺真实类目、完整必填/可选属性、允许值、标题计数规则 | 当前页面全量记录和官方规则引用；店铺/类目/页面变化重审 |
| supply_and_qualification | 该目的地、该服务确有供给及所需资质 | 服务方证明、有效范围/期限、业务审核人；过期或范围改变失效 |
| price_refund_fulfillment | 价格含义、真实承接能力、退改/售后/履约与商品相符 | 对应服务方案、报价及条款版本；变价/库存依据/服务条款变化重审 |
| destination_assets | 选定双标题版本、主图+4副图、详情数量/顺序、目的地/内容、使用权一致 | 素材清单和哈希、内容人工审核、权利依据；任何标题/素材变更重审 |
| dry_run_mapping | P4启动前：在目标店铺当前页面逐项核验全部执行字段的定位、交互方式、允许值及顺序，映射快照绑定当前商品和店铺 | 启动前保存映射版本/哈希、逐项核验记录及对应当前页面证据；定位器/字段/交互/顺序/页面变化重审。实际逐字段执行截图、提交前截图和执行日志属于P4完成验收资料及P5前提，不作为首次P4启动前已执行成功的要求 |

五项之外仍需按 [发布门槛](../RELEASE_GATES.md) 的阶段条件验证会话实际身份、线上重复、暂停/失效/验证码/恢复/失败隔离、授权及结果记录，不能用五项齐全代替全部阶段门槛。P4启动前的当前页面映射核验与P4完成后的实际执行验收分开留证；前者不能省略，后者不能倒置成首次P4启动的循环前提。

## 通用验收记录模板

```yaml
evidence_id: E-YYYYMMDD-module-001
claim: 单个可验证判断
level: E0/E1/E2/E3/E4
status: 待核验
shop_and_destination: 待核验或不适用
package_id_and_sha256: 待核验或不适用
code_and_mapping_version: 待核验或不适用
source_ids: []
collected_at: 待采集
performed_by: 待记录
reviewed_by: 待指定
method_or_command: 待记录
expected: 验收前写明
actual: 未执行
exit_code: 未执行或不适用
artifacts: []
counterevidence: []
limitations: 待说明
authorization_reference_and_scope: 未涉及真实发布
decision: 待审核
invalidated_by: 版本/页面/业务变更或有效期
```

原始执行日志与摘要分别保存，失败日志保留。截图需可定位实际步骤，并记录店铺、版本和时间；外发前脱敏。来源包含隐私时只保存受控引用，不把原件复制到公开静态目录。QA由不同于产出角色的复核环节执行；无人复核时写“待独立复核”，不填写通过签名。

## 冲突、失效与阻塞处理

1. 历史报告与当前代码不同：保留历史版本结果，运行适用的最小复验；未复验前不得宣称当前通过。
2. 用户业务意图与平台/供给资料不同：分开记录，事实未证实则阻塞对应商品；知识库不能补造授权或供给。
3. 规范之间矛盾：登记于 [冲突清单](INDEX.md)，交总负责人修订，QA按新版复验。文档修订不能抵消未解决的实现或业务失败。
4. 证据失效：标记失效、列出受影响商品/任务，停止依赖该证据的新执行；重新审核后方可恢复。
5. 汇报数字：明确统计时间、样本量、分母和数据源；100条历史READY与100条历史强校验失败分别记录，不能只取有利指标。
