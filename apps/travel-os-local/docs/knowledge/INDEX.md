## 使用入口

1. 判断现在能做什么：先读 [当前状态](../PROJECT_STATUS.md) 与 [发布门槛](../RELEASE_GATES.md)。
2. 找业务、技术原件：使用下方资料库。
3. 遇到旧包、审核或映射问题：使用经验库。
4. 输出判断：按 [信息源清单](SOURCES.md) 查证，按 [证据规则](EVIDENCE_RULES.md) 留存依据。
5. 原件变化时：更新对应索引、结论状态和受影响任务；历史文件保留，禁止覆盖历史失败来制造成功记录。

## 入库与维护

资料由对应产出岗位维护，总负责人管理索引，QA检查可追溯性。每条新增资料需包含编号、类型（原始资料/经验/结论）、来源、采集时间、适用店铺/目的地/版本、证据链接、限制、负责人和复核状态。未分配真实人员时写“待指定”，不虚构签名。

新经验使用 L 编号记录触发问题、有效做法、失败做法、复跑命令与适用边界；新结论使用 D 编号列出支持和反证。过期或被推翻的结论标记失效并链接替代记录。客户个人信息、订单隐私、密码、Cookie、验证码、Token及浏览器配置不入库；业务证明使用脱敏副本或受控原件引用。
