## 2. 五秒为什么不一致

当前正式 `publishing-materials.mjs` 的上传入口断言是 `expect(button).toHaveCount(1)`，没有显式 timeout。五秒来自 Playwright 的默认 expect 超时。页面 locator 默认八秒不覆盖 expect 的默认值。

几处预算原本服务于不同环节，而且没有统一记录：

- **卡片 4 秒**：查询现有素材的探测窗口；没有命中才走已有的素材库上传路径。
- **详情 iframe 20 秒，允许调用方最高 30 秒**：等待同一个官方详情选择器以及搜索/确定控件。
- **入口隐式 5 秒**：独立的断言超时；即使后续允许 60 秒上传，前面仍会先失败。
- **回执 60 秒**：选定文件之后，等“1 个文件上传成功”。
- **上传后卡片 30 秒**：等待素材列表显示。

本候选保持 4 秒探测和 60 秒回执，明确详情上传入口为 20 秒、上传弹窗每次等待为 8 秒、详情缩略图为 30 秒，iframe 仍为原 20 秒/上限 30 秒。它们不是合并成一个总超时，也不是靠固定休眠等待成功。

原有的“选文件前最多重开一次上传弹窗”继续保留，没有增加上传文件次数。只有真实就绪才提前结束；验证码/身份 guard 原样中断。截止检查阻止超预算的就绪结果被接受；正在执行的浏览器操作或 guard 不会被强行取消，因此实际退出时间仍可包含该操作耗时和截图落盘时间。

## 3. 隔离复现及实测

使用序号 12 原任务指定的详情首页 PNG，只读核对原 SHA-256 后在独立无头浏览器解码，实际尺寸 1086×1448。所有网页请求均本地返回或直接阻止，没有访问正式淘宝页面，也没有连接执行 Chrome。

在测试中明确注入“6.5 秒后出现”的延迟，观察结果如下。**6.5 秒是受控测试条件，不是从历史平台日志推算出来的响应速度。**

| 隔离情景 | 旧判据实测 | 候选实测 |
|---|---:|---:|
| 上传按钮延迟出现 | 5,050.733 ms 后断言失败，点击 0 次 | `upload-entry` 6,510.571 ms 就绪；含弹窗和偏好核对整个调用 6,604.927 ms；点击 1 次，文件上传 0 次 |
| 目标缩略图延迟出现 | 相同五秒可见断言形态 5,003.228 ms 失败 | `thumbnail` 6,548.499 ms，唯一可见并真实解码后通过 |

缩略图旧断言测试复现的是五秒可见断言机制，没有伪造已经缺失的历史 URL 前缀。原始记录和受控复现分开保存于 [隔离复现](evidence/isolated-reproduction.json)。

其他检查覆盖：可见节点但尚未解码、破图、零尺寸、重复卡片、上传入口缺失/禁用、成功回执夹杂上传中、验证码/身份错误、超过截止时间才就绪、详情 iframe 错误来源、已插入详情前缀恢复，以及真实 `ExecutionSteps` 的 `STEP_PAUSED` 落盘。

`STEP_PAUSED` 现有字段实际是 `name/error/durationMs`，没有改成新的事件 schema。缩略图超时的 `error` 带 `stage=thumbnail` 和原因，`errorCode` 仍为 null；完整 `stage/selector/expected/actual/screenshot/dom_snippet` 写入旁路诊断 JSON。验证新就绪超时仍被现有分类器归为 `SYSTEM`；没有实现 Step 2 的可继续执行分类。
