# 网站商品总表、批量选择与异常恢复

日期：2026-10-11。范围来自用户本轮授权：“先统一总表和状态，再打通批量执行与异常恢复，最后用网站完整操作验收。”现有执行器继续复用，首页及无关功能不改。

## 日常使用

1. 刷新工作台，进入 **产品库**。选择店铺、资料包，即可看到该资料包全部目的地。原图片资料库从“图片与资料”进入，可返回总表。
2. 按“等待执行、异常待处理、结果待核验”等状态筛选，也可搜索目的地、标题、商品 ID 或按国家筛选。每页 20 条；“选择筛选结果中的待处理项”覆盖筛选后的所有页。
3. 勾选后点击“检查所选待执行商品”或“检查并重试所选异常”。检查结果列出可以纳入的商品、排除原因及整批阻塞原因。
4. 通过检查后确认范围，再进入 **自动化任务** 核对并开始。保存范围本身不启动上架。原执行器每轮最多 100 条，只在本次确认的商品中自动衔接；暂停、停止及人工恢复仍从任务页操作。
5. 商品异常时查看该行的原因和“查看详情”。已核验成功的商品不会继续留在当前异常筛选中，历史异常与处理记录仍保留。断线时先“核对原创建结果”，保留原操作编号，不重新创建一份。

**当前原任务仍在 3/3 恢复预算限制内暂停。** 本版没有增额或自动恢复；不应把“总表已上线”理解为当前原任务已经可以继续发布。原商品及未结束窗口必须按原详情中的处理条件解决，新的勾选不能绕过它们。

## 状态口径

同一店铺、资料包内每个商品身份只计一次。发布状态互斥，资料校验状态单独展示，不混加统计。

| 网站状态 | 含义与处理 |
| --- | --- |
| 待创建 | 尚未建立执行任务；资料通过仍不等于可以发布 |
| 等待执行 | 原任务尚未执行；执行前继续检查资料、店铺、范围和权限 |
| 执行中 | 当前正在处理，不能再次勾选提交 |
| 已发布并核验 | 原记录包含商品 ID、平台状态、原行内容、截图和核验时间；不等于全部商品当前都在出售 |
| 异常待处理 | 原任务异常；是否可重试由原预算、提交证据和恢复检查决定 |
| 待人工处理 | 登录、验证码或其他原人工条件需要处理 |
| 结果待核验 | 已提交、提交不明确或完整证据不足；只核验原商品，不能重发 |
| 资料待补 | 导入或原预检存在资料问题；回 Excel / 图片文件夹修改，再导入核对 |
| 已跳过 | 原人工跳过决定保留，不因刷新重新进入发布队列 |

真实 700 条只读对账：292 已核验（69 已有 + 223 新增）、166 等待执行、1 异常待处理、131 待核验或隔离、1 待人工、109 资料待补，合计 700。原轮次仍记录 167 PENDING，其中一个暂停在款式步骤，网站归入异常；未改写原状态。资料维度另有 110 条待补，不可与发布状态的 109 相加。

## 执行与恢复边界

- 新建选择范围绑定原清单、店铺、商品身份、任务哈希、授权版本和原预检状态，支持不连续勾选。超出原清单、未审核资料包或非当前执行入口只能查看，页面说明原因。
- 保留原图片组合、随机属性、商品标题、run/queue ID、checkpoint 和已用次数。选择新导入的资料包不会替换旧任务快照；界面注明旧资料来源。
- 明确属于单商品资料问题且确认未提交时，记录该商品并继续其他合格商品。共享文件故障、登录/验证码、系统识别故障、提交结果不明等会暂停，不做无限重试。
- 成功、未知提交、人工处理、旧内容隔离、预算耗尽及未结束原断点不能通过重新勾选绕过。预检与正式创建期间状态变化会作废原检查。
- 创建使用持久原请求编号；已落库但响应丢失，或提交事务后出现未知异常时，保留原编号核对。不会凭前端超时判断“未创建”。
- 不新增发布者；网页不逐条发送重试请求。原协调器负责串行执行、最多 100 条分窗和范围内自动衔接。停止网页或进程后保留范围，不表示自动重启发布。
- 无固定审核清单的新资料包，本轮支持完整查看与状态汇总，需先从原自动化任务入口建立并审核执行范围；本版不替操作者补齐业务授权。
