# 自动化任务页参考图实施 · 2026-09-25

## 范围与授权

用户先要求按 `codex-clipboard-ec715668-01ce-431d-a38c-5b6f1365b703.png` 规划，随后明确回复“执行”。本轮实施工作台 `travel-os.html#tasks`，属于 P2 UI；不是商品发布操作或平台验收。

沿用 ui-ux、ui-ux-pro-max 的质量要求，以及 product-design:image-to-code 的参考图拆解、同尺寸截图比较方式。执行前已检查现有任务数据结构与操作入口。共享文件包含其他页面的并行修改，本轮只调整任务页相关函数及资源注册，未整体回退。

## 实现

- 顶部执行店铺、实际 Chrome 状态、打开浏览器、次级批次选择和创建批次。
- 双卡展示最近/当前批次、所选商品、批次进度与计数，以及当前执行状态、恢复原因、操作和可展开日志。
- 主图、副图、详情三组素材就绪进度，点击进入所选店铺产品资料。
- 七列任务表、带计数的分类、目的地/标题搜索、每页 10 条及翻页。
- 手机优先展示状态卡，素材纵向排列，任务表仅在自身内部横向滚动。
- 蓝色品牌、持久化点击折叠侧栏、既有首页链接和工作台导航保持原有约定。

主要文件：`workbench/tasks.css`、`workbench/task-view-model.mjs`、`workbench/travel-os.js` 中任务页函数。`travel-os.html` 引入样式，`static-files.mjs` 注册两项静态资源。

## 数据口径与交互

- 批次处理进度的“已结束”包含跳过、取消和仅填写完成；已核验上架只计入后端明确的 SUCCEEDED/VERIFIED 展示状态。
- 素材就绪要求该产品导入校验无问题，且主图 1 张、副图 4 张、详情存在文件。它不是上传完成量。截图中的 670/700 来自当时实际导入数据。
- 未发生的开始/结束时间展示 `—`；1800 秒来自批次已用时，不伪装可编辑超时配置。
- 不同店铺的准备单隔离显示。未适配店铺不提供批次执行入口。
- 准备单“核对此商品并入队”直接可见；开始与恢复仍使用既有确认表单。
- 验证码、提交中、待核验任务阻止批次重试入口；未知结果只走原有人工核验入口。
- 断线时状态卡即时更新并禁用写操作。校正仅涉及页面表达，后端执行协议与冻结内核不变。

## 保留差异与验收边界

产品标题、状态与素材数量使用现有数据；所选商品使用统一目的地图标，不把未经核验的城市照片当作产品素材。未添加参考图中的虚构账号、自动重试或超时设置。

这是实现者的本地 UI 自检，未代替独立 QA 或平台发布验收。未重新跑与本页无关的全站端到端流程，也未发起真实上架。
