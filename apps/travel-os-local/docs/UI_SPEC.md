## V1 现行界面（2026-09-21）

当前为已有稳定上架链路的本地运营产品层，使用原生 HTML/CSS/JS，不引入新框架。六模块侧栏，首页状态/下一步优先；任务与记录用可检索表格、筛选和分页，日志/素材用独立详情弹窗。执行模式、暂停原因、恢复条件必须可见；生成队列与执行明确分开，验证码只提供人工处理入口。1440px 桌面与 390px 窄屏实测无页面横向溢出，窄屏表格在容器内横向查看。键盘焦点、空状态、断线提示和禁用按钮已核验。当前页面与证据以 `product.js`、`product.css` 和 `output/workbench-v1-20260921/` 为准；下方为历史评审。

## 产品认知

- 阶段：半成品运营工作台。
- 表面类型：桌面端、状态优先的电商运营工具。
- 首要任务：明确下一步是登录、导入还是处理异常，而不是浏览全部数据。
- 气质：克制、可信、密度适中；避免营销页和卡片堆砌。
- 1440px 主视图，窄屏时优先保留当前任务、批量操作与异常。

## 当前页面实测

`workbench/index.html` 与 2026-09-03 本地截图显示：左侧导航、店铺会话、导入区、队列表和操作记录已存在；主路径可见，颜色和状态区分清楚。

需要在 P2 修正：

1. “资料齐全”当前只检查店铺匹配、标题和主图路径，不能作为发布就绪状态；改名为“文件预检通过”，并显示缺少类目/供给/资质/价格证据的阻塞提示。
2. 队列表把本地绝对路径直接放进主单元格，干扰识别；路径移入详情或复制按钮。
3. 首页统计不应靠人工记录文案替代真实任务结果；当前显示“淘宝发布结果：未接入”，只在 P5 实测后记录。
4. 队列是 100 行长表，应增加国家/城市、阻塞项、任务状态筛选和详情抽屉；复杂编辑不要塞进表格。
5. 所有模式和危险动作必须有明确状态、原因和下一步，LIVE 不得出现在未通过发布门槛的主操作中。

## 验收
