# N02｜会话归属与店铺身份闸门

日期：2026-09-13。范围：在既有工作台增加执行前会话核验；不改变商品供给、映射真实性、最终提交权限或发布阶段。

## 原问题与实施目标

旧代码把 CDP 连接成功显示为“已就绪”，没有核对端口所属浏览器的专用配置，也没有将当前页面的店铺身份绑定到执行。B01静态文件隔离已完成，本模块处理B02的工程缺口。

三个状态必须分开：连接成功、配置归属已核验、当前页面身份经人工核验且动态检查仍有效。只有最后一项及所有商品闸门同时满足才能填写；这不等于商品获得发布许可。

## 归属检查依据

Chrome官方协议的 `Browser.getBrowserCommandLine` 只在浏览器使用 `--enable-automation` 启动时返回命令参数，且该接口标记为experimental。依据为 [官方协议定义](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json) 中的同名方法（2026-09-13查证）。

工作台仅比较专用配置目录及调试端口，不读取或导出浏览器配置、Cookie、密码和令牌，不保存完整命令行。不能证明归属时拒绝复用，不能把失败解释为已登录；不会擅自关闭用户浏览器。不同Chrome版本与真实专用窗口兼容性仍须实测。

## 人工确认和执行规则

1. 操作者在专用浏览器打开正确店铺的目标草稿页。该页面的店铺名称定位必须经人工核验提供，不内置猜测的淘宝CSS。
2. 确认提交包含当前会话标识、店铺名、名称定位和人工核对声明；名称必须与目标店铺匹配，并能在当前页唯一且可见地读取。
3. 确认只保存在进程内，绑定会话代际、店铺配置、页面及地址；不能跨重启、断线、切店或切页继承。到期或页面名称不再匹配后重新核验。
4. 开始执行与执行器本身都复核会话；只使用已确认且与映射草稿地址匹配的当前页，不自动另开页面或导航后沿用旧确认。
5. 每个字段动作前复查名称和风险，继续保留提交前人工核验。未知、变化和风险先暂停；恢复不能绕过新身份核验。

以上是本轮实施合同；实际代码、验证及独立QA结论在下方收口记录，不以合同文字替代实现。

## 实现限制

当前仅接受HTTPS的myseller.taobao.com、seller.taobao.com卖家页；其他实际域名须先取证再调整。确认要求唯一合格卖家页、唯一可见身份元素，10分钟后失效。页面、配置、连接变化或风险使旧确认失效；操作人须先把已审核草稿页打开，执行器不会代为导航。

CSS必须由人工确认代表账户店铺身份；字符串相同不证明供给或真实账户归属。忙时暂停/取消立即使身份闸门失效并返回409，但已发出的单个浏览器动作不能撤销，操作者须按提示重试以保存暂停/取消状态。字段动作之间的复查也不构成平台原子事务。
