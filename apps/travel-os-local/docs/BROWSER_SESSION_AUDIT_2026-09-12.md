## 本轮结论

已有独立 Chrome 会话实现，不重复建设。浏览器连接不等于淘宝登录有效，更不等于实际店铺身份正确；当前模块尚不能按“账号与登录态已验收”交付。本轮仅新增本报告，不修改运行状态，不启动浏览器，不访问淘宝，不读取浏览器凭证文件。

## 待修复项（按优先级）

1. **浏览器配置目录的 HTTP 访问边界。** `server.mjs:604` 的静态服务允许读取工作台根目录下的已知文件路径，未排除 `.runtime`。已知运行文件路径可进入该分支；浏览器配置也在该目录下，存在暴露风险。应限定可访问的前端资源和必要证据目录，并拒绝运行数据、浏览器配置及越界路径。本轮仅静态核查，没有请求或读取凭证文件，也未验证具体浏览器文件是否可读。
2. **登录态与身份缺失。** 当前 `connected` 只证明端口可连接。正常登录页未必出现“登录失效”等现有风险词，连接到错误账户也可能继续。应独立记录连接状态、登录检查状态和人工店铺核验状态；无可靠证据保持“待人工确认”，禁止标记为已登录或可执行。
3. **CDP 归属没有验证。** `connect` 按端口连接；启动接口发现端口已连接即复用，没有确认该浏览器确由目标配置目录启动。其他浏览器占用端口时可能错误复用。新增店铺以 `9222 + shops.length` 分配端口，也没有占用检查。应在连接复用前核验归属，无法确认则阻塞。
4. **凭证边界需准确表述。** 工作台没有直接导出 Cookie 的调用，但使用持久化 Chrome 配置目录，不应把“不复制 Cookie”解释为浏览器不持久化登录数据。不得读取、导出或复制配置目录；跨电脑由操作者重新登录。登录提示字段只应填写非敏感备注，不输入密码、验证码或令牌。

## 后续验收定义（尚未实现或执行）

先修复静态文件访问边界，作为下一轮唯一小模块：允许首页及其资源正常加载；使用合成的非敏感文件验证 `.runtime`、源码与越界路径被拒绝；不拿真实凭证做测试。保留必要的截图查看与模板下载，并检查资源回归。

随后单独推进登录态模块：连接与身份确认分别展示；无确认、断线重连、登录失效、账户变化或归属不明均不能沿用“已就绪”；执行前复核目标店铺。人工确认应绑定当前店铺与会话，保留时间和非敏感说明，不采集凭证。

真实浏览器验收必须由操作者在目标店铺专用窗口登录，分别验证正确店铺、错误店铺、登录过期、验证码暂停、断线恢复与两店隔离。所需目标店铺及页面证据均待人工确认。任何测试不得点击最终发布。
