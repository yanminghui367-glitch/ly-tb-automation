# 2026-10-13 当前商品“跳过并继续本轮”

## 目标与范围

在任务轮次详情中，为当前已暂停商品提供一次明确的“跳过此条并继续本轮”操作。它只补足现有单条人工跳过流程；不改变资料、批次范围、执行器或商品发布规则。

## 操作和保护

1. 只在详情属于当前轮次与当前窗口、商品是当前项、轮次已暂停且原窗口仍可恢复时显示合并操作。
2. 操作者填写跳过原因后，页面先调用既有 `POST /api/v1/rounds/item-skip`。后端只在队列证据确认尚未提交时，原子记录 `MANUAL_SKIPPED` 与审计记录；商品不会再由该轮次提交。
3. 仅收到已记录跳过的回执后，页面再调用既有 `POST /api/v1/rounds/resume`，沿用同一轮次、窗口、清单摘要和稳定请求 ID。恢复仍受原登录、内核、执行许可与执行器守卫控制。
4. 网络断开或回执丢失时，页面保留原请求标识供重试核对，不生成新跳过决定。若跳过成功但恢复失败，会明确提示跳过已保存、继续未确认，并保留原恢复入口。
5. 已提交、提交结果不明、验证码/人工处理、非当前商品、范围变化或执行者仍运行时，不把商品伪装成安全跳过；后端既有保护保持有效。

## 修改文件

- `workbench/round-item-detail.js`：增加合并操作、作用范围检查、稳定请求与分阶段反馈。
- `workbench/round-item-detail.css`：合并操作的布局及窄屏样式。
- `workbench/travel-os.js`：绑定当前暂停轮次信息，并顺序调用现有跳过和恢复接口。
- `workbench/kernel-lock.json`：更新受保护页面逻辑的哈希和版本说明；不改发布内核。
- `workbench/scripts/round-item-retry-ui-qa.mjs`：在隔离网页里覆盖跳过后继续完整路径。
