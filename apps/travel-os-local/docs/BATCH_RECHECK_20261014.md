# 批次跳过筛选与异常、跳过重新上架｜2026-10-14

用户要求在当前批次任务列表增加“跳过”筛选，并增加对范围内异常、跳过商品重新检索并执行上架的按钮。

界面已在正式网站生效：当前第四批可筛出6条手动跳过任务，保持每页20条、批次下拉、搜索和日志。“重新检索并上架”按钮也已加入；但正式执行服务尚未加载新接口，且存在此前的素材校验文件版本差异，因此按钮明确显示暂不可用。不能将本次代码和隔离检查完成表述为真实重试已可用或已执行。

## 实现与范围

- `task-view-model.mjs` 增加独立skipped筛选，包含手动跳过、预检跳过及旧队列跳过；“已结束”仍包含跳过，筛选不更改商品状态。
- `travel-os.js` / `tasks.css` 增加按钮、服务能力检测、检查结果与范围确认。处理当前选择批次的全部异常和跳过项，不被当前页或搜索词意外缩小。普通待执行和成功项不纳入；尚未加载新接口、版本校验失败、断线、执行中均禁用。
- `operations-api.mjs` 在原selection路由内增加recheck模式及只读capabilities接口；`round-selection.mjs` 保留原执行者、固定清单、授权、原任务和队列，重新检查资料、内容审核、历史提交证据、次数和运行状态。`round-windows.mjs` 仅允许经过recheck选择验证的跳过项重新进入原队列。
- 预检只读。确认后在同一事务中封存原已暂停批次、保存选中范围与原跳过基线、将通过检查的跳过项重新排队，然后调用原start接口。原未执行但未入选的商品保留；不自动扩大范围或衔接整份清单。另一批次尚未结束、存在未纳入的断点、真实验证码、结果不明、成功或次数用尽等仍阻塞或排除。
- 重试不重抽图片/标题、不新建重复商品身份、不删除原run或提交证据、不重置attempts或增加预算。原窗口封存的跳过结果及历史事件保留，新尝试继续累计。来源窗口ID存于新增可空列 `round_selections.origin_window_id`，旧选择保持兼容。
- 创建与开始请求各保留稳定请求编号。回执丢失、刷新或重新点击只核对同一请求；若创建成功而开始检查未通过，保留原新建范围等待核对，不另建批次。新批次仍由原服务端登录、店铺、内核与发布闸门控制。
