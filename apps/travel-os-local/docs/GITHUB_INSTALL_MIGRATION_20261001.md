# 跨电脑安装与同数据迁移 · 2026-10-01

用户要求当前版本、网站 UI 和实际功能完整同步到 GitHub，并能在另一台 Windows 电脑安装；另确认商品 Excel、图片、报价和上架历史通过本地迁移包传递。范围是现有实现，新增真实发布为 0。执行者自验不替代独立 QA 或平台验收。

## 下载与安装

仓库：[ly-tb-automation](https://github.com/yanminghui367-glitch/ly-tb-automation)。工作台位于 `apps/travel-os-local/`，与仓库根目录原 FastAPI 系统分别运行。原系统保留，两套系统没有新增数据同步。

1. 在新 Windows 电脑安装 Node.js 24+、Python 3.10+，并确保 `node`、`npm`、`python` 可在终端运行；安装标准目录中的 Google Chrome。安装过程需要连接 npm 软件源。
2. 下载 GitHub 默认 `main` 分支的 ZIP 并解压，或执行 `git clone https://github.com/yanminghui367-glitch/ly-tb-automation.git`。
3. 进入 `apps/travel-os-local/`，双击 **`安装工作台.cmd`**。脚本按两个锁文件安装工作台与独立 V2 引擎依赖，检查语法、冻结内核、程序与资源 SHA-256；结果保存于 `.runtime/install/verification.json`。安装脚本不启动发布服务。
4. 需要同数据时，先恢复下述业务包；没有业务包则首次运行为空库。
5. 双击 **`启动上架工作台.vbs`**。首页是 `http://127.0.0.1:4318/`，点击“打开工作台”进入八模块；原操作台在 `/index.html`。

## 恢复本地业务包

将原电脑的 `TravelOS-business-data-20261001.zip` 通过移动硬盘/可信文件传输复制到新电脑；将 ZIP 拖到应用目录中的 **`恢复业务数据.cmd`**。必须在首次启动前恢复，已有业务数据或浏览器目录会拒绝覆盖。也可以在应用目录运行：

```powershell
node tools/migration-data.mjs restore --archive "业务包的完整路径.zip"
```

恢复器验证每个文件的大小/SHA-256、ZIP 路径、两份 SQLite 完整性、商品导入/任务/历史/报价/准备单数量与内核版本。业务文件放在本应用目录中，原机的 C/D 盘路径重定位到新位置，不要求新电脑同样有 D 盘。恢复报告在 `workbench/.runtime/migration-report.json`。

原始数据库和 JSON 快照另留在 `workbench/.runtime/migration-original/`。只对新数据库副本中的路径引用做重定位，商品标识、平台 ID、文件内容哈希、状态、模式、原审核哈希及历史事件保留来源；不会用迁移倒改审核结论。重定位后的任务内容哈希可能不同，继续暂停任务前需要人工预览、核对来源及恢复条件。源 Excel/原 JSON 商品包本身保持原字节，包内文字不批量替换。

迁移后的执行许可强制关闭；不创建登录 Profile，不自动启动/继续任务。先在新电脑的专用 Chrome 人工登录，再检查商品、素材、48 条历史记录和资料路径；需要继续生产时再按现有闸门手动开启。两个副本的数据不会自动同步；同店继续执行应选定唯一工作副本，避免两台分别维护的状态库产生交叉重复。

## 重新生成快照

```powershell
node tools/sync-source.mjs "待同步的 apps/travel-os-local 目录"
node tools/migration-data.mjs export --archive "新业务包.zip" --aliases "经哈希核对的路径映射.json"
```

导出器仅对白名单业务状态做 SQLite 在线一致备份，不读浏览器目录；原机有 RUNNING/SUBMITTING 状态会拒绝，导出中业务数据库或配置变化也会拒绝。业务包仅代表生成时点，不包含之后的变化。发现缺失文件或历史文件哈希变化会列入报告，不能当作补证通过。
