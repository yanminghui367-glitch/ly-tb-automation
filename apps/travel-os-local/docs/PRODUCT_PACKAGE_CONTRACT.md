# 商品包与字段映射契约｜P3

## 目的

商品包由运营人员上传。工作台不会猜测淘宝页面字段、类目或服务承诺；要进入自动填写 DRY_RUN，包内必须含一份已人工核验的、可追溯的 `automation_mapping`。

状态为 `READY` 或 `NEEDS_REVIEW` 的商品包均可导入工作台。`NEEDS_REVIEW` 只用于把待核验资料带入审核、预览和监督反馈；它不能被勾选、创建任务、打开卖家页或触发浏览器。旧版商品包不会被自动补写字段：缺少双标题、人工选题、4 张副图或详情图顺序时会显示为“商品包待修复”，不能创建任务。

工作台可为单条商品保存一份**本机补充记录**，仅包含两个标题版本、人工选题和四张副图路径。它用于让运营人员补齐自己确认的资料，不写回原始 JSON；可在工作台中撤销，重新导入仍会保留。类目、价格、供给、资质、退改和服务承诺不属于补充记录，仍只能来自用户商品包和可复核审核资料。

工作台导入区可下载 `product-package-template.json`。它是空白结构模板，故意使用 `status: "NEEDS_REVIEW"`，全部类目、价格、供给、证据和页面定位器均为空；它不能直接导入或创建任务。操作人只能在填入真实资料、逐项核验当前卖家页字段后改为 `READY` 并上传，不能把占位文本当作证据。

存在本机补充记录时，工作台可导出一份合并后的商品包 JSON 副本，便于留档或再次上传。导出不会覆盖原文件，也不会改变商品的审核状态；未保存补充记录时不提供导出，避免产生看似完整的空白文件。

## 基础商品数据

保留当前字段：

- `package_version`、`status: "READY"`、`source`
- `listing.destination`、`listing.location_type`、目的地代码
- `listing.title_versions`：**恰好两个且不重复**的标题版本；`listing.selected_title_index`：人工选中的下标（`0` 或 `1`）；`listing.title`：必须与所选版本完全一致。
- 国家级：`listing.location_type: "country"`、`listing.country` 与 `listing.destination` 一致，且不得填 `listing.city`；城市级：`listing.location_type: "city"`、`listing.city` 与 `listing.destination` 一致。当前使用标题必须包含该目的地。
- `assets.main_image`、`assets.secondary_images`（恰好 4 张且不重复）、`assets.detail_images`（按固定展示顺序给出且不重复）
- `release_profile`、`checks`、`result`
- `review_evidence`：五项发布证据。

国家级和城市级均为单链接，不设 SKU。业务数据缺失或未确认时保持阻塞，不要填入占位服务承诺。

同一店铺内，工作台把相同的“国家级 + `listing.country`”或“城市级 + `listing.city`”视为重复商品包：重复包不能创建或执行 DRY_RUN，也不能打开单条卖家页。操作人须人工核对后保留一条，再重新导入商品包；此检查只基于工作台当前导入的本地商品包，**不代表**已经查询淘宝线上在售链接。

所有素材路径必须能在执行工作台的本机读取，且后缀只能为 PNG、JPG、JPEG 或 WEBP。相对路径以商品包 JSON 所在目录解析；通过浏览器上传、无法取得本机 JSON 绝对路径的商品包，素材应提供绝对本机路径。工作台不会把远程 URL、占位路径或不可读取文件当作可上传素材。

### 在工作台选择文件夹上传

选择“商品包与素材文件夹”时，工作台会把该次选择中的 JSON 和 PNG/JPG/JPEG/WEBP 图片暂存到本机运行目录，再用暂存后的 JSON 所在目录解析相对素材路径。它只改变工作台的本地副本，不改写原始商品包或素材。单次最多 300 个 JSON、1200 个素材文件、素材合计 80MB；文件夹中未被选择、非图片文件、远程 URL 和越出包目录的路径都不会被当作可上传素材。若商品包引用的图片没有随文件夹一起选择，文件预检仍会阻塞该条商品。

最小结构示例（路径仅为用户本地商品素材，不代表平台素材已通过审核）：

```json
{
  "listing": {
    "location_type": "country",
    "country": "英国",
    "destination": "英国",
    "title_versions": ["英国自由行服务咨询", "英国旅行行程定制咨询"],
    "selected_title_index": 0,
    "title": "英国自由行服务咨询"
  },
  "assets": {
    "main_image": "用户提供的主图路径",
    "secondary_images": ["副图1", "副图2", "副图3", "副图4"],
    "detail_images": ["详情图1", "详情图2"]
  }
}
```

## automation_mapping 结构

```json
{
  "platform": "taobao",
  "version": "由运营人员维护的版本号",
  "verified_evidence": "当前卖家页面截图编号、录屏路径或可复核链接",
  "draft_url": "经人工确认的 HTTPS *.taobao.com 商品发布页地址",
  "fields": [
    {
      "id": "title",
      "locator": { "strategy": "人工确认后的定位方式", "value": "人工确认后的定位值" },
      "source": "listing.title",
      "interaction": "fill"
    }
  ]
}
```

工作台仅校验结构，不预置任何淘宝选择器。`fields` 至少要包含以下 `id`，且每项都有 `locator.strategy`、`locator.value`、`interaction` 与 `reviewed: true`（由操作人逐项在当前卖家页核验后标记）：

- `category`
- `title`
- `price`
- `main_images`
- `secondary_images`
- `detail_images`

实际页面有其它必填项时，必须一起加到映射中；这六项只是最低要求，不是淘宝完整字段清单。`interaction` 只允许 `fill`、`select`、`upload`、`manual`：执行器没有点击、提交或发布动作。原生下拉可使用 `select`，页面无法稳定自动化的字段应标为 `manual`，任务会暂停等待人工处理；操作人确认该字段已手工完成后，执行器会跳过该字段继续，已成功填写或上传的字段也不会重复执行。

映射窗口中的“逐项核验”清单对应这六项最低字段。缺少字段、定位器或交互方式时不能勾选；对已录入的字段，操作人须在当前卖家页逐项核验后勾选，工作台才写入 `reviewed: true`。额外的库存、属性等字段也必须逐项核验，当前需在映射 JSON 中为该字段明确写入 `reviewed: true`；不能因为它不在六项清单中而免于审核。`manual` 字段的勾选只表示该字段已确认需要人工填写，不代表它在后续任务中被自动填写。任何重复字段 ID、未核验字段、或不完整定位器都会继续阻塞 DRY_RUN。`required` 只能是布尔值，省略等同于 `true`；设为 `false` 仅允许来源值缺失时跳过该字段，不能免除字段审核。

创建 DRY_RUN 任务时，工作台会冻结映射版本、页面证据、草稿页地址和全部字段的执行顺序、来源、定位器、交互方式、核验状态及必填规则，并生成本机指纹；同时冻结商品包状态、目的地、标题、素材、类目/价格/履约资料和五项审核证据。每条任务还会固定创建当时的本机准入结论，供后续审计导出追溯，但不包含字段定位器、素材绝对路径或外部证据地址。草稿地址必须是已人工核验的 `https://*.taobao.com`，实际打开卖家页之前会重新校验当前映射并比较快照；映射或商品包任一变化、或旧任务缺少任一种快照，任务立即暂停且不打开卖家页。LY08 使用 `snapshotVersion: 2`，旧版仅冻结六项字段的快照也会阻塞，不自动升级。操作人须重新审核、逐项核验映射、取消旧任务后新建任务，不能直接恢复旧任务。

只要商品包被未结束的 DRY_RUN 任务引用，工作台就拒绝修改本机补充记录、审核证据和字段映射，并说明对应任务编号。操作人须先人工取消旧任务，再修改和重新审核，避免正在排队或恢复中的任务与新资料混用。

`locator.strategy` 只能为 `css`、`label`、`text`、`testid` 或 `role`；使用 `role` 时还必须填写 `locator.role`。工作台的首次编辑模板故意留空版本、证据、草稿页和定位器值，它只能帮助录入结构，不能让任何任务解锁。

### 当前卖家页证据采集

在“字段映射”窗口可以点击“记录当前页面”。它只会读取当前店铺专用 Chrome 中**已经由操作人打开**的 `https://*.taobao.com` 页面，保存一张本地截图、页面标题和地址；它不会新建页面、导航、填写、上传、读取 Cookie，或点击提交/发布。工作台仅在映射中的 `draft_url`、`verified_evidence` 为空时，把当前地址和本地截图引用预填到 JSON，现有人工填写的内容不会被覆盖。

每条商品主记录最多保留 12 条采集记录；重新导入同一商品包时，这些本机记录会保留，映射窗口只显示最近三条的时间、风险状态和截图入口。它们不写回原始 JSON，也不自动成为发布审核证据。

若当前页出现滑块、验证码、登录失效或其他风险提示，工作台只保留现场截图，且不会写入映射；操作人必须在专用 Chrome 手动完成验证后重新采集。截图是人工核验线索，不等同于已确认全部类目、字段或平台许可。

## 准入与执行

1. 先在当前店铺页面由人工确认真实类目和所有必填字段。
2. 将页面证据写入 `verified_evidence`，再将经核验的映射随商品包上传。
3. 先通过商品包强校验，再补齐五项 `review_evidence`，才允许创建 DRY_RUN 任务。
4. DRY_RUN 使用 `draft_url` 打开经确认的发布页，按映射填写每一步并保留截图和事件记录，在最终提交前自动停止。
5. 登录、验证码、滑块、风控、页面变化和类目不匹配一律暂停，由人工处理后恢复；不得绕过。
