# 星途 Travel OS

2026-09-23，来源：本轮用户要求、现有代码、已有运行记录及本轮隔离验证。面向本机单人操作的旅游商品自动化上架系统；不是旅游预订站、普通 ERP 或生图工具。

## 入口与首要任务

用户的最新修正优先：`/` 保持原星途地球首页；“打开工作台”进入 `/travel-os.html#overview`。首页视觉不因工作台产品化重做。工作台品牌与底部链接可返回首页。`/index.html` 保留原操作台及已验证的上传入口。

运营首先确定目的地，再核对产品、报价、目标店铺和执行条件。正常使用从一键启动入口开始，无需 Codex 或命令行。

## 信息架构

| 模块 | 首要决定 | 对应事实 / 动作 |
| --- | --- | --- |
| 总览 | 处理哪个目的地 | 3D 地球、搜索、产品数、历史报价、已上架店铺、最近任务 |
| 自动化任务 | 当前到哪里、是否需要介入 | 左队列、中流程节点及日志、右店铺/Chrome/异常/控制 |
| 店铺管理 | 管理或登录哪家店铺 | 动态注册卡片、新增、检查、专用浏览器、移除管理 |
| 产品库 | 商品资料是否齐备 | 只读导入快照、标题、素材顺序、问题、状态 |
| 目的地中心 | 查看哪个国家/城市的资源 | 同一地理标识关联产品、报价和已覆盖店铺 |
| 报价库 | 成本还是销售报价 | 用户已确认两类都需要；原始币种与计价单位、供应商、有效期、历史 |
| 上架记录 | 执行结果能否核验 | 实际平台 ID/状态/截图、异常、来源批次与执行日志 |
| 资料设置 | 来源和执行环境是否有效 | 本地 Excel/图片、检查结果、人工开启执行许可 |

## 对象与边界

- 地理标识使用 `[type,country,city]`，用于跨产品关联报价；执行判重仍使用原有 `destinationKey(shopId,type,country,city)`，不替换内核标识。
- 报价是独立且保留历史的人工录入数据。成本与销售明确区分，不用商品售价填充历史，不换汇、不自动调整商品售价。
- 准备单可取消；执行批次不能当普通表格记录删除。所选目的地可核对后复用原队列生成单商品 DRY_RUN 任务，不自动开始。正式模式继续使用已有热度批次入口。
- 执行相关操作仍使用原队列、恢复检查、串行锁、幂等回执和上限。验证码由人工处理；结果不明只能核验。暂停请求不等于断点已保存。
- 移除店铺只移出此工作台管理列表，保留身份、浏览器数据与历史；待处理执行或待核验记录阻止移除。新店铺登录状态不等于发布适配已完成。
- 已验证的内核有店铺约束；新增店铺的自动发布尚未验收。所选目的地单项入口暂不升级 LIVE；无人值守自动重试未启用。
- 本轮不触发真实上架，不修改源表，不读取登录凭证，不重写十个冻结内核文件。
